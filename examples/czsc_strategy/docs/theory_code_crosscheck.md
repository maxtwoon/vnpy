> **分层前提**：本项目分两层消化理论——
> - **信号计算层**（`chan_strategy/signals.py`、`chan_strategy/sell_signals.py`、`czsc_adapter.py`）：
>   确定性计算，只产出信号键值，书摘中的判据条款适用于此层；
> - **报告/叙事层**（`chan_strategy/html_report.py`、`skill_build/`、诊断报告）：
>   书摘中"报告中必须注明……""LLM 要求……"类条款只适用于此层，不应反灌进信号计算。

## 8. 书摘对 czsc 的行为断言 —— 已实测核实（2026-07-29，探针存档）

书摘包含两条对 czsc 库行为的断言，已用项目解释器（C:\Python314，czsc==1.0.0rc8）跑只读探针核实，
证据见 `diagnostics/research/misc/czsc_rc8_theory_probe_report.md`（可复现脚本 `diagnostics/czsc_rc8_theory_probe.py`）：

- ✅ **"czsc 的 ZS 默认是笔中枢"——证实**。官方类型存根 `ZS.bis: list[BI]`（「获取构成中枢的笔列表」）；
  实测 `ZS(bis=[BI×5])` 构造成功，构成元素全部为笔。**附带重要发现**：rc8 的 `CZSC` 本体**没有 `zs_list` 属性**，
  只完成包含处理、分型与笔识别，不自动构建中枢——本项目自研 `build_zhongshu_from_bis()` 是必要实现。
  另注意 `CZSC.max_bi_num` 默认 50，`bi_list`/`finished_bis` 长序列会被截断。
- ❌ **"三类买卖点 = czsc 内置五笔/七笔/九笔（倒1/倒2）形态信号"——证伪（对 rc8）**。
  rc8 无 `czsc.signals` 子模块；全包扫描无"三买/三卖/五笔/七笔/九笔"任何命中；
  `CZSC.signals` 只是空缓存槽（OrderedDict），`generate_czsc_signals` 只执行用户自备的信号函数。
  该 API 形态属于旧版 czsc。因此项目自研三阶段状态机是当前唯一实现；
  将来若要 czsc 原生形态信号做交叉验证，须自行移植旧版信号函数或放弃该路线。
- ⚠️ **附带口径提醒**：ZS 的 `sdir`/`edir` 是中枢**内部**首/末笔方向，与书上"中枢方向 = 进入段方向"
  口径不同，不可直接用作书义中枢方向。
