# 缠论择时策略方案 v1.1

## 1. 修订目标

本方案依据《择时策略研究框架》和《信号函数》重构现有缠论分析系统。系统目标不是直接预测涨跌，而是把市场结构转换为可复核信号，再通过因子、事件和持仓策略形成可回测的交易决策。

本次修订解决以下问题：

- 现有 `czsc_adapter.analyze()` 输出结构数据，但 `bsp_state_machine.decide()` 直接生成交易动作，缺少标准的 `Signal → Factor → Event → Position` 分层。
- 一买、二买、三买的简化条件被直接视为交易触发，缺少历史买卖点、持仓状态和次级别确认。
- 未区分“完全分类信号”和“仓位调整信号”，难以评价单个信号的信息增益和稳定性。
- 缺少统一的持仓风控、回测、样本外检验和版本管理规则。

## 2. 总体架构

```text
行情数据
  → 多周期 K 线与 CZSC 结构计算
  → 标准信号字典
  → Factor（信号组合）
  → Event（开平仓事件）
  → Position（持仓、止损、超时、交易间隔）
  → CzscStrategyBase / CzscTrader
  → 回测、回放、绩效评估
```

### 模块职责

| 层级 | 职责 | 当前模块处理 |
|---|---|---|
| 结构层 | 输出分型、笔、笔中枢、背驰证据 | 保留并完善 `czsc_adapter.py` |
| 信号层 | 将结构状态转换为标准信号字符串 | 新增标准信号函数模块 |
| 组合层 | 用 `all / any / not` 组合信号 | 使用 `Factor`、`Event` |
| 持仓层 | 保存交易上下文并执行风控 | 使用 `Position` |
| 策略层 | 组合多个独立持仓子策略 | 继承 `CzscStrategyBase` |
| 执行层 | 多周期联立、回测与回放 | 使用 `CzscTrader` |

`bsp_state_machine.decide()` 不再作为最终交易执行器。它可保留为解释层或候选信号生成器，但所有真实交易动作必须由 `Event + Position` 产生。

## 3. 信号设计规范

### 3.1 标准表达

所有信号统一使用：

```text
k1_k2_k3_v1_v2_v3_score
```

- `k1`：周期，如 `30分钟`。
- `k2`：观察对象与参数，如 `D1BI`、`D1ZS`、`D1BSP`。
- `k3`：信号名称及版本，如 `方向V260615`。
- `v1/v2/v3`：分类结果；未使用位置填 `任意`。
- `score`：0 至 100 的预留打分字段；当前只记录，不参与事件匹配或交易决策。

示例：

```text
30分钟_D1BI_方向V260615_向下_确认_任意_80
30分钟_D1ZS_位置V260615_中枢上方_任意_任意_70
5分钟_D1BSP_底背驰V260615_疑似_创新低_任意_60
```

信号版本进入名称，修改判定逻辑时必须创建新版本，禁止静默改变历史信号含义。
可信度、风险级别等交易语义应使用明确的分类信号表达，不能隐含在 `score` 中。

### 3.2 信号分类

**完全分类信号**用于描述当前市场状态，每次计算必须且只能落入一个类别。例如：

- 最后一笔方向：`向上 / 向下 / 无有效笔`
- 价格相对中枢位置：`中枢上方 / 中枢内 / 中枢下方 / 无中枢`
- 数据充分度：`充分 / 不足`
- 背驰状态：`无 / 疑似 / 确认 / 失效`

**仓位调整信号**只描述是否满足操作条件，例如：

- `一买候选 / 一买确认 / 非一买`
- `三买回抽确认 / 三买失效 / 非三买`
- `止损触发 / 超时触发 / 未触发`

完全分类信号应先验证分布、稳定性和区分能力；仓位调整信号必须通过持仓策略回测验证。

### 3.3 信号质量约束

- 只使用已确认结构生成交易信号；末笔、末中枢等未确认结构只能生成观察信号。
- 数据不足、预热不足或字段缺失时，输出明确的降级分类，不得默认解释为买卖点。
- 单级别背驰只能输出“疑似”；“确认”必须由次级别结构或其他明确规则确认。
- 实验性线段模块未通过验证前，不得用于开平仓事件。

## 4. 买卖点事件设计

### 4.1 一买

一买是左侧交易，只允许小仓位试错。

候选因子：

- 当前级别向下离开中枢并创新低；
- 离开段力度弱于进入段，形成疑似底背驰；
- 次级别出现底背驰确认或底分型确认；
- 排除数据不足、结构未确认和跌停等不可交易状态。

事件：

```text
一买候选 → 仅观察
一买确认 → 开多试仓
继续创新低或止损触发 → 平多
```

### 4.2 二买

二买必须依赖已发生的一买或等价的趋势反转锚点，不能仅用“回抽未创新低”判定。

候选因子：

- 持仓上下文存在有效一买记录；
- 一买后向上离开，随后次级别回抽；
- 回抽低点高于一买低点；
- 次级别底分型或向上结构确认。

跌破一买低点时，二买假设失效。

### 4.3 三买

三买必须拆分为“离开、回抽、确认”三个阶段：

1. 向上有效离开中枢；
2. 次级别回抽；
3. 回抽低点不进入中枢上沿 `ZG`，随后再次向上确认。

仅凭“最后一笔向上且低点高于 `ZG`”只能生成三买候选信号，不能直接开仓。

卖点按对称逻辑设计；平仓事件优先级高于开仓事件。

### 4.4 事件配置示例

以下配置表达“30 分钟三买结构已确认，且 5 分钟回抽确认后开多”。实际信号名称必须与已实现的信号函数一致。

```python
open_long = {
    "name": "三买确认开多",
    "operate": "开多",
    "signals_all": [
        "30分钟_D1ZS_数据状态V260615_充分_任意_任意_0",
    ],
    "signals_not": [
        "30分钟_D1ZS_结构状态V260615_未确认_任意_任意_0",
    ],
    "signals_any": [],
    "factors": [{
        "name": "三买离开回抽确认",
        "signals_all": [
            "30分钟_D1BSP_三买阶段V260615_回抽不入中枢_任意_任意_0",
            "5分钟_D1BSP_回抽确认V260615_向上确认_任意_任意_0",
        ],
        "signals_any": [],
        "signals_not": [],
    }],
}
```

`signals_all` 表达必须同时满足的条件，`signals_any` 表达至少满足一个的条件，`signals_not` 用于排除未确认、数据不足或不可交易状态。事件只负责操作触发，止损、超时和重复开仓约束由 `Position` 负责。

## 5. 持仓子策略与风控

每种买点建立独立 `Position`，分别评估，不在一个状态机中混合：

| 子策略 | 操作定位 | 建议风控 |
|---|---|---|
| 一买多头 | 左侧试仓 | 小仓位、较紧止损、较短超时 |
| 二买多头 | 回抽确认 | 以一买低点为结构失效位 |
| 三买多头 | 趋势跟随 | 以中枢 `ZG` 或回抽低点为失效位 |

每个 `Position` 必须配置：

- `interval`：限制同类事件频繁重复开仓；
- `timeout`：超过指定基础周期 K 线仍未兑现则退出；
- `stop_loss`：提供统一的硬止损底线；
- `T0`：按交易品种明确设置；
- 独立开仓与平仓事件，禁止依赖无持仓上下文的即时决策。

结构止损和 `Position.stop_loss` 同时存在时，先触发者执行。股票策略还必须排除涨停开仓、跌停平仓等不可成交状态。

## 6. 多级别与策略组合

- 基础周期负责交易执行和超时计数。
- 交易周期负责识别中枢与买卖点，例如 30 分钟。
- 次级别负责确认背驰、分型和回抽，例如 5 分钟。
- 更高级别只用于环境过滤，不直接触发低级别交易。

策略类继承 `CzscStrategyBase`，其 `positions` 属性返回独立子策略列表。先分别评估一买、二买、三买，再决定是否组合。不得仅因多个子策略同时存在就假设组合收益更优。

## 7. 研究与验收流程

1. **信号验证**：检查每个完全分类信号是否穷尽、互斥、无未来函数，并统计样本分布。
2. **事件验证**：检查 `signals_all / signals_any / signals_not` 是否符合设计语义。
3. **单策略回测**：分别回测每个 `Position`，记录胜率、盈亏比、最大回撤、持仓周期和交易次数。
4. **稳健性检验**：执行样本外、滚动窗口、不同品种和不同市场阶段测试。
5. **交易回放**：抽查信号触发点，确认没有结构错配和未确认结构泄漏。
6. **组合评估**：只有单策略通过验收后，才评估组合相关性和资金分配。

禁止只以总收益评价策略。策略至少应满足：无未来函数、交易样本数量充分、样本外结果未显著失效、最大回撤可接受、关键参数轻微变化时结果稳定。

## 8. 实施优先级

### P0：纠正交易语义

- 新增标准信号函数，将结构数据转换为 `k1_k2_k3_v1_v2_v3_score`。
- 将二买绑定历史一买上下文；将三买拆分为离开、回抽、确认。
- 禁止 `suspected` 背驰直接触发开仓。
- 用 `Event + Position` 替代 `decide()` 的最终交易动作。

### P1：建立研究闭环

- 为一买、二买、三买分别创建持仓子策略。
- 增加信号分布测试、事件测试、持仓风控测试和交易回放。
- 建立可重复使用的信号缓存与批量回测流程。

### P2：扩展能力

- 接入经验证的多级别分析模块。
- 线段算法通过独立正确性测试后，再评估是否进入交易信号。
- 完善策略 JSON 导出、版本记录和实盘适配。

## 9. 当前方案迁移边界

- `czsc_adapter.py`：继续作为结构层，但应补齐全量字段白名单验证，并明确输出字段的确认状态。
- `bsp_state_machine.py`：降级为解释/观察模块；其 `BUY_* / SELL / REDUCE` 不再直接用于实盘。
- `xd_segment.py`：继续保持实验性，不进入交易链路。
- `tests/test_basic.py`：由基础不变量测试扩展为信号、事件和持仓行为测试。

完成 P0 后，系统才具备“可回测择时策略”的基本定义；完成 P1 并通过样本外检验后，才可讨论模拟盘或实盘接入。
